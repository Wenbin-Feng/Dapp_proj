# 2026-10-25 功能验收与演示数据

## 结果与范围

针对 `https://dapp-proj.vercel.app` 完成真实 Supabase Web3 签名登录、数据库业务 API 和浏览器操作验收。创建并保留 **6 个独立 QA 钱包/资料、10 件商品**；不修改原有用户/商品，不执行云端建表 SQL。商品业务保持 `PRODUCT_BACKEND=database`。

- 线上 API：46 项检查通过，包含同一测试运行中已验证的恢复检查点。
- 线上浏览器：13 项检查通过；实际访问生产网站和 Supabase，没有拦截或伪造业务响应。测试使用 Node 中的独立 QA 私钥提供 EIP-1193 登录签名，不导入、操作用户的 MetaMask；扩展自身的弹窗未做人工验收。

**本轮没有签署 Sepolia 写交易。** 转币、双向兑换、滑点/期限、授权、LP 添加/移除、PDC 商品购买及维修的写流程，在本地真实 Hardhat 合约与浏览器集成中通过。可选 `PRODUCT_BACKEND=chain` 尚未在线上启用，其云端增量 SQL、索引和 Sepolia 商品结算不列为已完成的公网验收。

## 手动复现

两个脚本均为显式手动命令，不接入 CI、不增加应用登录后门。第一次会真实创建测试账号及数据；相同 `--run` 从私有日志恢复已完成的业务步骤，避免重复插入。全新运行应换一个日期/后缀，例如 `2026-10-26-a`。

```sh
node scripts/live-acceptance.mjs --live \
  --app-url https://dapp-proj.vercel.app \
  --env-file /absolute/path/to/.env.local \
  --run 2026-10-26-a --expiry-fixtures

node scripts/live-browser-acceptance.mjs --live \
  --app-url https://dapp-proj.vercel.app \
  --run 2026-10-26-a
```

API 脚本需要 Supabase URL 和 publishable key；只有 `--expiry-fixtures` 需要服务端 secret key。浏览器脚本使用首次脚本生成的 QA 钱包，不需要拿用户钱包的私钥。仅对明确获准的应用运行。

私钥、会话和过程日志保存在本机被 Git/Vercel 排除的 `tmp/live-acceptance/<run>/`；私钥文件权限为 600，运行目录为 700。不提交私钥，不把这些测试钱包用于真实资产。匿名截图、QR 下载和去敏报告也保存在同一运行目录。保留数据供演示，清理时须按运行记录精确匹配，不能清空业务表。
